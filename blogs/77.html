CI/CDとは
Continuous Integration（継続的インテグレーション）/ Continuous Delivery（継続的デリバリー）」の略称。
すばやくアプリケーションを開発し、ユーザーへ提供することで競争力を保つことを目的としている。
CI
開発者にとっての自動化のプロセス。
複数のエンジニアのソースコードを逐一統合し、正常に動作するか検証もすること。
流れ：pushまたはpull リクエスト->テスト->マージ->もう一度テスト
具体的には、
GitHubにpushすることで、GitHubActionsを起動し、Jestでテストを行うなど。
CD
ユーザーに継続的にアプリケーションを提供すること。
テスト済みコードのリポジトリへのリリース（本番環境へのデプロイ）を自動化すること。
小さな変更を頻繁にユーザーへ届けることを目的としている。
具体的には、GitHubActionsでGitHubPagesにデプロイすることなど。

Jest
JavaScriptのテストを簡単に行える
インストール
$ npm i -D jest
実行
$ npm test
これを行うと、プロジェクト内のすべてのテストファイルを見つけてテストを実行するらしい
テストファイルとは
->Jestはtest.jsで終わるファイルやtestディレクトリ内にあるファイルをすべてテストファイルとして認識する
特定のファイルだけ実行したい場合
$ npm test {ファイルまたはパス名}

Jestの導入
ReactでJestを使ってテストをしてみる
必要なパッケージをインストール
$ npm install -D jest jest-environment-jsdom @testing-library/react @testing-library/dom @testing-library/jest-dom
TypeScriptを使っている場合は
@types/jest
もインストールするが
今回はJSを想定

追記
Next.jsには、next/jestというモジュールが入っており、Next.jsアプリをJestでテストするための設定を自動で組み立ててくれる。
=>jest.config.js（Jestの設定ファイル）を短縮できる

やってくれること/ 中身
JSX/importの変換 / SWCで変換する(Babelの設定が不要になる)
CSS・画像のモック / import './style.css' や import logo from './logo.png' でエラーにならないよう、空の偽物に差し替える
@/ エイリアスの解決 / jsconfig.json / tsconfig.json の paths を読んで、自動で効かせる
.env の読み込み / テスト中も process.env に環境変数が入る
next.config.js の反映 / Nextの設定をテスト側にも引き継ぐ
無視設定 / node_modules や .next を変換・テスト対象から外す

しかし、FreeBSDはサポートしていない。
そのため、JSXやimportの変換の作業ををBabelで行わなければならない。

Babelの導入（追記）
$ npm i -D babel-jest @babel/core @babel/preset-env @babel/preset-react

package.jsonに追加
--package.json
  "scripts": {
    "dev": "next dev --webpack",
    "build": "next build --webpack",
    "start": "next start",
    "lint": "eslint",
    "deploy": "BASE_PATH=/seichou-project npm run build && gh-pages -d out --dotfiles",
    "preview": "npm run build && serve out",
    "test": "jest",<--追記
    "test:watch": "jest --watch"<--追記
  },
これで
$ npm run dev
$ npm run test:watch
が動くようになる

Jestの設定ファイルを作る
ルート直下に以下のファイルを作成
--jest.config.js
module.exports = {
  bail: 1, //何回テストが失敗したときにテストを中止させるか
  testEnvironment: "jest-environment-jsdom", //Jestのテスト実行環境を設定するためのオプション。デフォルトではNode.js。フロントエンドのテストをする場合はjsdomを通してブラウザのような環境でテストをすることもできる
  testMatch: [
    "**/__tests__/**/*.js", //どのファイルがテストが書かれたファイルかを設定する。正規表現。
    // "**/?(*.)+(spec|test).[tj]s?(x)"
  ],
  moduleNameMapper: {
    "^@/(.*)$": "<rootDir>/$1",
  }, //@/app/... を <プロジェクトルート>/app/... に読み替える。<rootDir> は jest.config.js がある場所
  transform: {
    //どのファイルを何で変換するか。.js / .jsx を babel-jest で変換する
    "^.+\\.jsx?$": [
      "babel-jest",
      {
        configFile: false, // babel.config.js を探さない
        babelrc: false, // .babelrc を探さない
        presets: [
          //babel/preset-envは、import/export、新しい文法を翻訳するが
          //targetsを指定しないと古いブラウザでも動くように、何でも古い書き方へ変換してしまう。
          // でもテストが動くのはNodeの中だけで、ブラウザは関係ないので、「node: "current"」で今のNodeで読めない部分だけ変換する設定にしている。
          ["@babel/preset-env", { targets: { node: "current" } }],
          //babel/preset-reactは、JSX（<コンポーネント名　/>のやつ）を翻訳する
          //runtime: "automatic"は、変換に必要な部品(Reactの関数)を、Babelが自動でimportしてくれる
          //Next.jsのコンポーネントは、普通 import React を書かないので、この設定にしないと動かない
          ["@babel/preset-react", { runtime: "automatic" }],
        ],
      },
    ],
  },
  testPathIgnorePatterns: ["/node_modules/", "/src/"], //テスト対象外となるパスのパターン
  verbose: true, //各テストの結果を一覧表示する
};
